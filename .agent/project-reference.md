## 1. Project Overview

| Field | Value |
|-------|-------|

| **Description** | Anti-coercion layer for banking apps: a duress credential opens a decoy session, transfers are held and a silent alert is raised. |
| **Type** | Library (Spring Boot starter) plus a demo REST API |
| **Stack** | Java 21, Spring Boot 4.1.2, Spring Web MVC, Spring AOP |
| **Build tool** | Maven multi-module |
| **Runtime version** | Java 21 (Temurin in CI) |

| **Source root** | `<module>/src/main/java/io/github/valossa515/decoyguard/...` |
| **Test root** | `<module>/src/test/java/io/github/valossa515/decoyguard/...` |
| **Status** | Early prototype for research and portfolio purposes. Not production ready. |

### Problem and Purpose
Elderly people in Brazil are coerced, by phone or in person, into opening their bank app and making Pix transfers while the attacker watches. Blocking the transfer or asking for more confirmation does not help a victim who is being watched. Decoy Guard lets the user comply on screen without complying in reality.

### Key Flows
1. Login with the real PIN opens a NORMAL session. Calls reach the real services.
2. Login with the duress PIN opens a session that looks identical, switches it to DURESS and raises one silent alert.
3. In a DURESS session every call on a routed interface reaches the `@Decoy` bean. A Pix returns a normal receipt, lowers the decoy balance and is stored as a `HeldTransaction`.
4. The fraud desk reads the held transactions of a session.

## 2. Architecture

* **Style:** library with a framework-agnostic core and ports (SPIs), a Spring Boot adapter (starter), and a sample application (demo).
* **Packaging:** by module, then by feature inside the demo (`account`, `auth`, `fraud`).
* **Base package:** `io.github.valossa515.decoyguard`

### Module Map

| Module | Package | Responsibility |
|--------|---------|----------------|
| `decoy-guard-core` | `...decoyguard.core` | Model (`SessionMode`, `DuressContext`, `HeldTransaction`, `SilentAlert`), SPIs and in-memory defaults. No runtime dependencies. |
| `decoy-guard-spring-boot-starter` | `...decoyguard.spring` | Auto-configuration, `@Decoy` routing, request filter, default extractor and alert publisher. |
| `decoy-guard-demo` | `...decoyguard.demo` | Fake bank API used by tests and by the README walkthrough. |

### External Integrations

None yet. Every storage and delivery concern is an SPI with an in-memory or logging default.

## 3. Module and Class Map

### Core (`decoy-guard-core`)

| Class | Kind | Responsibility |
|-------|------|----------------|
| `SessionMode` | enum | `NORMAL` (real data, real effects) or `DURESS` (decoy data, effects held). |
| `ActivationTrigger` | enum | `DURESS_CREDENTIAL`, `RISK_SIGNAL`, `MANUAL`. |
| `DuressContext` | record | Session id, mode, trigger and activation time. `anonymous()` is always NORMAL. |
| `DuressContextHolder` | final class | ThreadLocal binding of the current context. `current()` falls back to anonymous NORMAL. |
| `DuressActivator` | class | Switches a session to DURESS and publishes exactly one `SilentAlert` per activation. Swallows and logs alert failures. |
| `DuressSessionRegistry` | SPI | `activate` (idempotent, first wins), `resolve`, `release`. |
| `InMemoryDuressSessionRegistry` | default | `ConcurrentHashMap` registry with an injectable `Clock`. Single instance only. |
| `HeldTransaction` | record | Transaction shown as successful but never sent: id, sessionId, type, amount, counterparty, heldAt. |
| `HeldTransactionStore` | SPI | `hold`, `findBySession`. |
| `InMemoryHeldTransactionStore` | default | Per-session `CopyOnWriteArrayList`. |
| `SilentAlert` | record | sessionId, trigger, raisedAt. Only built from a DURESS context. |
| `SilentAlertPublisher` | SPI | `publish(SilentAlert)`. Must not block the request for long. |

### Starter (`decoy-guard-spring-boot-starter`)

| Class | Kind | Responsibility |
|-------|------|----------------|
| `Decoy` | annotation | Marks a bean as the decoy for all its interfaces, or only those listed in `value()`. |
| `DecoyRoutingPostProcessor` | BFPP + BPP | Hides `@Decoy` beans from autowiring, maps interface to decoy, rejects two decoys per interface, wraps real beans in interface-based JDK proxies that route per call. |
| `DuressContextFilter` | servlet filter | Resolves the mode once per request, binds it, clears it in `finally`. Writes nothing to the response. |
| `SessionIdExtractor` | SPI | Reads the session id from the request. |
| `BearerTokenSessionIdExtractor` | default | Uses the opaque bearer token as the session id. |
| `LoggingSilentAlertPublisher` | default | Logs the alert at WARN (trigger and time only). |
| `DecoyGuardAutoConfiguration` | auto-config | Always registers the post processor. Registers SPI defaults with `@ConditionalOnMissingBean` and the filter (order `HIGHEST_PRECEDENCE + 100`) when `decoy-guard.enabled` is not false. |

### Demo (`decoy-guard-demo`)

| Class | Responsibility |
|-------|----------------|
| `DemoApplication` | Spring Boot entry point. |
| `ClockConfiguration` | `Clock` bean in `America/Sao_Paulo`. |
| `account.AccountService` | Routed interface plus shared DTOs: `Balance`, `StatementEntry`, `PixRequest`, `PixReceipt`. |
| `account.RealAccountService` | Real account, balance 48,750.32, mutates balance and statement on Pix. |
| `account.DecoyAccountService` | `@Decoy`. Balance 312.47 minus held Pix, decoy statement, Pix stored as `HeldTransaction`. |
| `account.EndToEndIds` | Pix-shaped ids (E + 31 alphanumerics), shared by real and decoy. |
| `account.InsufficientFundsException` | "Saldo insuficiente", thrown by both implementations. |
| `account.AccountController` | `/account` endpoints. Knows nothing about duress. Maps insufficient funds to 422. |
| `auth.AuthController` | `/login`. Same response for real and duress PIN. Activates duress on the duress PIN. |
| `auth.DemoSessions` | Toy store of opaque UUID tokens. |
| `auth.SessionInterceptor` | Rejects `/account/**` without an open session (401). |
| `fraud.FraudDeskController` | `/fraud-desk/held`, stand-in for the bank back office. |

## 4. Available Endpoints (demo)

| Method | Path | Controller | Description | Auth |
|--------|------|------------|-------------|------|
| POST | `/login` | `AuthController` | Body `{"pin"}`. Returns `{"token"}`. 401 on wrong PIN. | No |
| GET | `/account/balance` | `AccountController` | `{"available"}` | Bearer |
| GET | `/account/statement` | `AccountController` | List of `{date, description, amount}` | Bearer |
| POST | `/account/pix` | `AccountController` | Body `{key, amount}`. Returns `{endToEndId, key, amount, at, status}`. 422 `{"error":"Saldo insuficiente"}`. | Bearer |
| GET | `/fraud-desk/held?session=` | `FraudDeskController` | Held transactions of a session (back office stand-in). | No (demo only) |

## 5. Database Schema

No database. State lives behind the SPIs (`DuressSessionRegistry`, `HeldTransactionStore`) with in-memory defaults. Redis and JDBC implementations are on the roadmap.

## 6. Conventions Summary

| Concern | Choice |
|---------|--------|
| Data access | SPI interfaces in core, in-memory defaults |
| DI style | Constructor injection, routed services injected by interface |
| Error handling | Shared exceptions between real and decoy, `@ExceptionHandler` in the controller |
| Auth | Demo only: opaque bearer token, no Spring Security |
| Logging | `System.Logger` in core, commons-logging in the starter |
| Test framework | JUnit 5 + AssertJ |
| Integration tests | `@SpringBootTest` + `MockMvc` (demo), `ApplicationContextRunner` (starter) |

See [conventions.md](conventions.md) for details.
